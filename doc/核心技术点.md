# MinosIE 核心技术点

> 「会动的简历」——用一段动画演示"从零写出简历并逐段美化"的全过程。
> 技术栈：Vue 3.4（`<script setup>` + TS）· Vite 5 · Prism.js，**零第三方 Markdown / 动画库依赖**。

## 一、自研 Markdown 渲染管线（`src/utils/markdown.ts`）

不依赖任何 Markdown 库，完整实现三层架构：

| 层 | 函数 | 职责 |
| --- | --- | --- |
| Lexer | `parseMarkdown(src)` | 逐行扫描切分块级结构 |
| Parser | `parseInline(src)` | 块内行内语法解析（`**粗体**` / `*斜体*` / `` `行内码` `` / `[链接](href)` / 图片） |
| Renderer | `renderBlocks` / `renderInline` | AST → HTML |

- 支持的块级类型：frontmatter（`---` 元数据）、标题、段落、列表、引用、围栏代码块、表格、分隔线
- 每个块节点记录 `line`（1-based 源码行号），便于把 AST 与源码位置关联
- `compile(src)` 一次完成解析 + 渲染 + 统计（字符数 / 行数 / 块数 / 内联节点数 / 耗时 ms），返回 `ParseResult & { html }`
- 所有插值经 `escapeHtml` 转义，天然防注入

**踩坑案例（值得记住的教训）**：段落分支的排除正则里含 `\|`，而表格分支要求"下一行是分隔行"——当打字进行到表格首行的孤立 `|` 时，两种分支都不消费该行，扫描指针 `i` 永不前进，`compile()` 死循环。修复方式：段落正则不再排除 `|`，让不完整表格行由段落分支兜底消费。**原则：逐字符扫描器必须保证指针在任意输入下都前进**。

## 二、五段式动画引擎（`src/pages/AnimatedResume.vue`）

```ts
type Phase = { kind: 'style' | 'md' | 'html'; text: string }
const phases: Phase[] = [
  { kind: 'style', text: SEG0 },        // 基础样式（含开场白注释）
  { kind: 'md',    text: fullMarkdown },// 逐字打出简历 Markdown
  { kind: 'style', text: SEG1 },        // 编辑器配色
  { kind: 'html',  text: '' },          // 切换到渲染视图
  { kind: 'style', text: SEG2 },        // 简历美化样式
]
```

- **驱动方式**：`requestAnimationFrame` 时间累积（`acc >= delay` 触发），非定时器，标签页隐藏/恢复不丢帧
- **按字符变速**：`delayFor(ch)` 依字符类型给不同延迟（换行、标点停顿更久），规则块写完后有一次性 `blockPause`（张弛节奏）
- **补打限幅**：一帧内最多补 3 个字符（`budget < 3`），应对偶发卡顿；后台积压直接丢弃，防止"突进"

## 三、三段式呈现：Markdown 源码 → HTML 渲染 → CSS 美化

右侧面板按 `enableHtml` 在两种视图间切换，形成"手写 → 渲染 → 美化"的三幕推进：

1. **先写 Markdown 源码**：`md` 阶段右侧用 `<pre class="md">` 逐字显示打字稿 `currentMarkdown`，光标跟随，呈现"从零手写简历"的过程
2. **再渲染成 HTML**：`html` 阶段把 `enableHtml` 置真，右侧切换为 `renderedHtml`（模块加载时由 `compile(fullMarkdown)` 一次性渲染，并经 mailto 注入，见下节）
3. **最后注入样式**：`SEG2` 阶段边打字边注入 CSS，实时重排已渲染的简历，呈现"逐步美化"的收尾

`enableHtml` 的完备性由三处保证：`advance()` 的 html 阶段置真、`skip()` 跳过时置真（任意时刻都能看成品）、`replay()` 重播时复位为假

## 四、增量 CSS 注入与语法高亮

- `flushBlock(raw)`：SEG 阶段每打完一条规则，立即注入 `<style>` 节点 → SEG2 打字时右侧简历**同步变美**
- `applyFullStyle()`：终态一次性注入完整 CSS，覆盖增量节点（跳过 / 重播共用）
- 高亮用 Prism.js + **增量状态机**（`hlPrefix` / `hlLastRaw` / `pending` / `topDepth`），已完成行缓存高亮结果，只重算当前行，避免全文重刷

## 五、mailto 占位符注入（`src/data/resumeSource.ts`）

- 打字稿里只写短占位符 `[✉️ 联系我](mailto)`——避免带 `subject` / `body` 预填文案的长 URL 在打字阶段逐字暴露
- 真实链接提为模块级常量 `resumeMailto`，渲染成 HTML 后由 `injectResumeMailto(html)` 一次性替换 `href="mailto"` 占位（`&` 转义为 `&amp;`）
- 功能与观感解耦：动画干净，成品链接完整

## 六、排版细节

- 姓名 / 学历 / 邮箱合并进同一行 `h2`：学历用 Markdown `*em*` 包裹渲染成 `<em>`，CSS 单独缩字号（`.55em`）与姓名（`2em`）拉开层级；邮箱链接同理缩至 `.42em`
- 全程无 router，`main.ts` 直接挂载单页组件，构建产物极小（JS gzip ≈ 45 KB）

## 七、工程化

- `npm run build` = `vue-tsc --noEmit && vite build`，类型检查前置
- GitHub Pages 部署：`vite.config.ts` 设置 `base: '/MinosIE/'`，本地 dev 需访问 `http://localhost:517x/MinosIE/`（端口被其他项目占用时 Vite 自动顺延）
- 数据与文案分离：`src/data/resume.ts`（结构化数据）→ `resumeSource.ts`（拼装打字稿 + mailto 注入）→ 组件只负责动画，改简历不动引擎
